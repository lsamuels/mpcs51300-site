============

- A mapping from variable names to integer values
- Represented as ``map[string]int``

The environment models the program's state as it executes.

Program Execution
-----------------

You must implement an ``Execute`` method for ``Program``.

.. code-block:: go

   func (prog *Program) Execute() bool {
   }

Execution Behavior
~~~~~~~~~~~~~~~~~~

The ``Execute`` method must:

1. **Validate the program**
    - Ensure all variables are declared before use
    - Ensure assignments only target declared variables
    - Ensure variable expressions only reference declared variables

2. **Return a boolean result**
    - Return ``true`` if **any error occurs**. If validation fails, execution must **not** proceed.
    - Return ``false`` if **no errors occur**

3. **Execute the program**
    - Only execute the program *after* validation succeeds
    - Statements execute in order
    - The environment should be updated as execution proceeds



Design Constraints
====================

- You must use:
   - Interfaces for shared behavior
   - Structs for concrete constructs
- You may **not**:
   - Hard-code logic using type switches in ``Program.Execute``
   - Collapse all behavior into a single function
- You **must**:
   - Implement behavior through method calls on statements and expressions

Design Hint: Separating Validation from Execution
==================================================

Before executing a program, you are required to verify that it is **valid**.
For example:

- Variables must be declared before they are used
- Assignments must target declared variables
- Variable expressions must reference declared variables

One clean way to organize this logic is to **separate validation from execution**.


Augmenting Interfaces (Optional but Recommended)
------------------------------------------------

You may find it useful to extend your existing interfaces with an additional method
that checks whether execution is safe.

For example, you might consider adding:

- A validation method for statements
- A validation method for expressions

These methods can walk through the program structure and verify correctness
*without* executing the program.


Tracking Declared Variables
--------------------------------

During validation, you need a way to track which variables have been declared.

A common approach is to use a map that represents a **set of variable names**:

.. code-block:: go

   declared := map[string]struct{}{}

In this map:

- The **keys** are variable names
- The **values** are empty structs

This map answers the question:
“Has this variable been declared yet?”


Why ``struct{}``?
~~~~~~~~~~~~~~~~~~

The empty struct type ``struct{}``:

- Takes **zero bytes** of storage
- Carries no data
- Exists only to indicate presence

This makes ``map[string]struct{}`` the idiomatic Go way to represent a **set**.


Adding to the Environment
~~~~~~~~~~~~~~~~~~~~~~~~~~

To record that a variable has been declared:

.. code-block:: go

   declared["x"] = struct{}{}

To check whether a variable exists:

.. code-block:: go

   _, ok := declared["x"]
   if !ok {
       // variable was not declared
   }


Why This Design Helps
--------------------------------

Separating validation from execution:

- Makes your code easier to reason about
- Prevents partially executed programs
- Mirrors how real compilers operate

A compiler always checks correctness *before* it attempts to run or translate a program.


Final Note
-----------

You are **not required** to use this exact design.
However, if you find yourself mixing validation logic directly into execution,
consider whether separating the two concerns might simplify your implementation.
